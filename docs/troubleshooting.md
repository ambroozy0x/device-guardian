# Device Guardian — Operator Troubleshooting Guide

This guide provides symptom-based troubleshooting procedures, root cause analyses, and verified recovery actions for Device Guardian operators.

---

## 1. Quick Diagnostic Triage

Whenever unexpected behavior occurs, begin by running the built-in diagnostic and health inspection commands:

```powershell
# Run full system diagnostics (checks sensors, config, and system permissions)
python -m device_guardian.main --diagnostics

# Inspect active runtime status and daemon health
python -m device_guardian.main --status

# Inspect configuration syntax and credential status
python -m device_guardian.main --check-config
python -m device_guardian.main --credentials-status
```

## 2. Startup & Process Issues

### Symptom: Service exits immediately upon launch
* **Root Cause 1: Configuration Validation Error**
  - **Check**: Run `python -m device_guardian.main --config-check`.
  - **Resolution**: Review the error message. Ensure all boolean fields in `.env` are strictly `true` or `false`, and numeric thresholds are within valid bounds.
* **Root Cause 2: Unsupported Python Version**
  - **Check**: Run `python --version`. Device Guardian requires Python 3.11 or 3.12.
  - **Resolution**: Upgrade or select a supported Python runtime.

### Symptom: `Another instance of Device Guardian is already running`
* **Root Cause: Single-Instance PID Lock Conflict**
  Device Guardian uses a file lock (`guardian.lock`) containing the active process PID to prevent duplicate instances.
* **Resolution**:
  1. Verify if an existing process is running:
     ```powershell
     # Windows PowerShell
     Get-Process -Name python* | Where-Object { $_.CommandLine -like "*device_guardian*" }
     ```
  2. If running, stop it gracefully:
     ```powershell
     python -m device_guardian.main --stop
     ```
  3. If the process crashed and left a stale lock file, Device Guardian automatically detects whether the PID is alive on next start. If manual intervention is required, delete the stale lock file:
     - Windows: `%LOCALAPPDATA%\DeviceGuardian\guardian.lock`
     - Linux/macOS: `~/.local/share/device-guardian/guardian.lock`

## 3. Sensor & Hardware Issues

### Symptom: Camera capture fails or times out
* **Log Signature**: `CameraError: Failed to open capture device 0`
* **Root Cause 1: Device in Exclusive Use**
  Webcam hardware is typically exclusive. If Zoom, Microsoft Teams, Skype, or the Windows Camera app is open, access is blocked.
  - **Resolution**: Close conflicting video applications.
* **Root Cause 2: Incorrect Device Index**
  If multiple cameras exist (e.g., external USB webcam + internal laptop webcam):
  - **Resolution**: Set `CAMERA_DEVICE_INDEX=1` in `.env` and verify with:
    ```powershell
    python -m device_guardian.main --test-camera
    ```
* **Root Cause 3: OS Camera Privacy Permissions**
  - **Windows**: Navigate to **Settings > Privacy & security > Camera**, and ensure **Allow desktop apps to access your camera** is ON.
  - **macOS**: Check **System Settings > Privacy & Security > Camera** and grant access to Terminal/Python.
* **Note**: Camera capture failure is non-fatal; Device Guardian falls back to text-only Telegram alerts.

### Symptom: Approximate Geolocation fails or reports `Unavailable`
* **Log Signature**: `Location query failed or timed out`
* **Root Cause 1: Internet Disconnection or Timeout**
  The device has no outbound route or DNS resolution is failing.
* **Root Cause 2: IP Geolocation API Rate Limiting**
  Free-tier endpoints (such as `ipapi.co`) enforce hourly rate limits.
  - **Resolution**: Device Guardian caches responses and handles rate limits gracefully. The alert pipeline will still complete and dispatch without coordinates.

## 4. Alert & Telegram Delivery Issues

### Symptom: Telegram alerts not received
* **Log Signature**: `Telegram delivery failed: 403 Forbidden` or `400 Bad Request`
* **Root Cause 1: Bot Blocked or Uninitiated**
  Telegram bots cannot initiate conversations with users.
  - **Resolution**: Open Telegram, search for your bot username, and click **/start**.
* **Root Cause 2: Incorrect Token or Chat ID**
  - **Resolution**: Run `python -m device_guardian.main --test-alert`. If it fails with `401 Unauthorized`, re-enter the token generated by `@BotFather`. If `400 Chat not found`, verify your numeric chat ID via `@userinfobot`.
* **Root Cause 3: Circuit Breaker Tripped (`CircuitBreakerOpenError`)**
  If Telegram API has experienced 5 consecutive network failures, the circuit breaker opens for 30 seconds to prevent thread starvation.
  - **Resolution**: Check internet connectivity. After 30 seconds, test again with `python -m device_guardian.main --test-alert`.

## 5. Detection & Log Ingestion Issues

### Symptom: Failed logins occur but no alerts are generated
* **Root Cause 1: Windows Security Audit Policy Disabled**
  Windows Event ID 4625 is only emitted if logon auditing is enabled in Local Security Policy.
  - **Resolution**: Open an administrative PowerShell prompt and run:
    ```powershell
    auditpol /set /subcategory:"Logon" /failure:enable
    ```
* **Root Cause 2: Insufficient Permissions (Linux / macOS)**
  On Linux, reading `/var/log/auth.log` requires membership in group `adm` or `systemd-journal`.
  - **Resolution**: Add your user to the appropriate group or run with necessary privileges:
    ```bash
    sudo usermod -aG adm $USER
    ```
* **Root Cause 3: Threshold Not Exceeded**
  Device Guardian only triggers when `FAILED_ATTEMPTS_THRESHOLD` (default: 3) failed logins occur within `ATTEMPTS_WINDOW_SECONDS` (default: 60s).
  - **Resolution**: Check `FAILED_ATTEMPTS_THRESHOLD` in `.env`.

## 6. Persistence & State Recovery

### Symptom: `State file corrupted or unreadable`
* **Root Cause**: An unexpected power outage or system crash occurred mid-write.
* **Resolution**:
  Device Guardian uses atomic write staging and maintains an automatic `.bak` copy.
  1. Inspect the recovery subsystem:
     ```powershell
     python -m device_guardian.main --recovery-status
     ```
  2. Execute automatic repair from the verified backup:
     ```powershell
     python -m device_guardian.main --repair-state
     ```
  3. Verify installation integrity:
     ```powershell
     python -m device_guardian.main --verify-installation
     ```
